# Engineering in Rust

A recorder runs for months and parses video from devices on your network. The engine is compiled Rust on the Tokio runtime, with GStreamer doing the media work. This page covers why, the rules the code keeps to, and how it is tested.

<a id="why-rust"></a>
## Why Rust

- **No garbage collector,** so nothing pauses the process while video arrives.
- **Memory safety checked when it is built,** for a program that handles input from cameras it does not control.
- **Ownership and `Send`/`Sync`,** which let one compressed unit be shared by many threads without copies and without data races.
- **Tokio** for the many sockets a recorder holds open: the control socket, camera events, plugins and the cloud link.

> **Why.** The failures that matter in a recorder are slow ones: a leak that runs out of memory after a week, a race that corrupts one recording in a thousand. Rust rules out whole classes of them at build time instead of in the field.

> **Trade-off.** GStreamer, which parses the media, is C. Rust's guarantees stop at that boundary, and camera media should be treated as untrusted input. The Rust side keeps its own work in GStreamer callbacks to wrapping a buffer and handing it on.

<a id="rules"></a>
## Rules the code follows

- No `unwrap()` or `expect()` outside tests and start-up, and no `panic!` in library crates: errors are returned.
- Typed errors with `thiserror` in libraries; `anyhow` only in binaries and tests.
- Never hold a `Mutex` or `RwLock` across `.await`: clone what is needed out of the lock first.
- An `appsink` callback finishes in under a millisecond: it wraps or copies the sample and returns.
- Bounded channels (`mpsc`, `broadcast`, `watch`) rather than shared state behind a mutex.
- Producers never block: a full queue drops by its own rule.
- `tokio::time::sleep`, never `std::thread::sleep`, in async code.
- Structured tracing fields (`cam_id = %id`), not formatted strings.
- `cargo fmt` and `cargo clippy -D warnings` before every commit.

<a id="lock-discipline"></a>
## Locks and long work

Shared application state sits behind one lock that is held briefly. Work that can take time, such as tearing down a camera's pipeline, reading the playback index or checking a network drive, happens off that lock, on a blocking thread or a task of its own. Tearing down a decoder that may hang is handed to a thread whose only job is to wait for it.

> **Why.** The control socket, the once-a-second recording scheduler and the view leases all need that lock. If a hung NFS mount or a stuck driver could hold it, the whole recorder would freeze.

<a id="testing"></a>
## Testing

- **Unit tests** in each module, for policies, parsing, layout and state machines.
- **Real GStreamer tests** that build actual pipelines on small generated video: for example, that a recording made through the shared connection is byte-for-byte the camera's bitstream, and that no video decoder or encoder runs on the recording and browser paths. They skip, saying why, when a needed element is not installed.
- **Fakes at the boundaries:** fake plugin sessions, fake service managers and fake clocks, so failure paths can be tested without real cameras.
- **Shared fixtures** for signed messages, so the recorder and the services it talks to are checked against the same bytes.
- **Desktop UI tests** run offscreen with stubbed readers. They check the logic, not frame rates on real screens.

> **Not done or not measured.** Hardware decoding paths are tested on the hardware the developers have. Some combinations, such as V4L2 on a Raspberry Pi with the running fallback, or GPU scalers in plugins, have not been run on real devices; the pages that describe them say so.

<a id="workspace"></a>
## The workspace

*Rust crates*

| Crate | What it is |
|---|---|
| `nw-backend` | The recorder service: the binary and its library. |
| `nw-core` | Shared types only: camera configuration, events, JSON-RPC messages, frame types. |
| `nw-analytics-protocol` | The plugin protocol's frames and messages. |
| `nw-analytics-sdk` | The Rust plugin SDK: transports, identity, decoded-picture rings. |
| `nw-cloud-protocol` | Types shared with NeuroWatch Cloud for browser viewing. |

The desktop app is a separate Python package (`ui/neurowatch`), with its own lint (`ruff`), type check (`mypy`) and tests (`pytest`).

<a id="licence"></a>
## Licence

The recorder, its desktop app and the free plugins are Apache-2.0. Contributions come in under the same licence, with no separate agreement to sign. New dependencies must be compatible with it: no GPL or AGPL code, and LGPL libraries only as separate, replaceable libraries (PySide6, GStreamer, an LGPL build of FFmpeg). The free edition's 16-camera limit is a build option, not a licence check: anyone building from source can change it.
